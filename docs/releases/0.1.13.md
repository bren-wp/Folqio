# Folqio v0.1.13 — Android deletion conflict preservation

## Changes
- Preserve UUID-named `.pending-delete` files when a live PDF of the same identity already exists, irrespective of library-index membership. Previously recovery silently deleted the pending copy even when its bytes differed.
- Maintain existing behavior for non-conflicting entries: restore pending files referenced by durable metadata and clean up unreferenced tombstones.
- Add regression coverage for conflicting pending and live file contents both when the index references the document and when it does not.
- Align Android versionName/versionCode and iOS marketing/build versions to 0.1.13 / 14.

## Scope and limitations
This is a focused data-loss prevention change, not a full editor release. Conflict artifacts remain in private app storage for future manual or app-assisted reconciliation. They are not automatically surfaced in the library UI. Existing limitations of rasterized Android PDF page operations, Android OCR and signing remain.

## Validation required before merge/release
- Android JVM unit tests, lint, debug APK, release AAB and R8/resource shrinking in GitHub Actions.
- macOS iOS simulator build and XCTest.
- Verify release assets; debug APK and unsigned AAB must be labeled accurately. Do not publish a release if required CI fails.
