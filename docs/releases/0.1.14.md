# Folqio v0.1.14 — Android lifecycle, UI consistency and dead-code audit

## Android fixes
- Retain the current document URI and page position using Compose saveable state across activity recreation/rotation. Resolve the opened document from the library rather than attempting to save a non-Parcelable `LocalPdf`.
- Avoid reimporting an incoming ACTION_VIEW document when an activity is recreated, while treating each subsequent ACTION_VIEW as a distinct event (even the same URI).
- Disable Home/Open/Scan/Photos/Merge and Settings ZIP export controls while the app is processing an operation.
- Reuse Folqio's existing mint palette token for PDF thumbnail placeholders; no visual identity changes.
- Reuse existing localized ZIP completion wording rather than a hard-coded English result.

## Source/code audit
- Scan main **and test** Kotlin source files for duplicate imports and top-level types.
- Review lexical potentially unused imports, private functions and XML/bitmap resource references conservatively; no declaration/resource is deleted based on textual search alone.
- Continue mandatory AndroidManifest permission, FileProvider, private storage/backup, Google Play SDK 36, R8/shrinking, version and CI release checks.
- Python unit tests for the audit tool (false-positive safeguards, duplicate imports/types and advisory cases).
- Existing Android unit tests and lint must pass in CI; manual screenshot and hardware verification are still pending.

## Boundaries and download safety
- Android only. Existing documents remain under user control, and PDF page editing remains **rasterized**, not lossless.
- Debug APK is **debug-signed**, for testing only. AAB is **UNSIGNED** without private upload-key material.
- No claim of 1:1 pixel parity, real-device verification, Google Play approval or complete dead-code elimination.
